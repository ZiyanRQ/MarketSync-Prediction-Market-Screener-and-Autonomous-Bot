# What I Built

A **cross-source stock comparison tool**: it takes one symbol and fetches a live quote for it from **two separate providers** — Alpha Vantage and Finnhub — then prints their values side by side with a difference column. This is a step past the crypto tracker: instead of comparing two *symbols*, it compares one symbol across two *sources*, which is exactly the shape MarketSync needs (the same market, priced by two venues, checked for discrepancy).

The throughline was the same universal skeleton — **fetch → check → parse → compare → display** — with two stages levelled up: "check" now inspects the JSON body (not just the status code), and "search" became "compare across sources."

## What's in it

- Both API keys loaded from `.env` via `load_dotenv()` + `os.getenv()` — the pattern set up on Day 10 but never actually used until now.
- `call_api_ALPHA_ADVANTAGE` runs `raise_for_status()` **and then** checks the body for `"Error Message"` / `"Note"` / `"Information"`, because Alpha Vantage returns `200 OK` with an explanatory message for bad keys and rate limits.
- A data-driven `FIELDS` table (label → Alpha Vantage key → Finnhub key) driving both the difference calc and the printed comparison — one source of truth instead of repeated blocks. *(Formatting/printing section was AI-assisted and labelled as such in the code.)*
- A `to_number()` helper that strips the trailing `%` off Alpha Vantage's `change percent` string and coerces to float, with `None` for missing/non-numeric fields.
- A three-column comparison table (Alpha Vantage | Finnhub | Difference) via `print_comparison`.

It runs and produces a clean comparison for a valid US symbol.

# Programming Concepts Learned

Today I learned / reinforced that:

- **A `200 OK` is not proof of good data.** Some APIs (Alpha Vantage among them) return `200` and then bury the real problem — bad key, rate limit — inside the JSON body. "Did the request succeed?" quietly becomes two questions: did the HTTP call succeed, *and* does the body actually contain a quote. `raise_for_status()` only answers the first.
- **The `.env` pattern earns its keep on keyed endpoints.** CoinGecko was open, so last time the pattern was theory. Two keyed providers made it real: key in `.env`, `.env` gitignored, read via `os.getenv()`, never a literal in the code or URL.
- **A data-driven field table beats repeated blocks.** One `FIELDS` list mapping a label to each provider's key drove the difference calculation *and* the printout — add a field once, it flows everywhere.
- **Normalise at the boundary.** Alpha Vantage hands back `change percent` as a string like `"1.0500%"`; Finnhub hands back a number. Stripping the `%` and coercing to float **once**, at the point the data enters my logic, means everything downstream can assume clean floats.
- **Free-tier rate limits are an architecture input, not an afterthought.** Alpha Vantage's free tier is ~25 requests/day (5/min); Finnhub's is 60/min. For a polling bot those aren't footnotes — they decide whether a source is even usable.

# Challenges

## Challenge 1 - Dead code and a phantom call in `get_api_Finnhub` *(found, left open)*

### Problem

`get_api_Finnhub` has two faults stacked in one function: several lines sit **after** a `return data or None` (unreachable), and it calls `call_api_Finnhub`, which doesn't exist anywhere in the file. It has never crashed — because nothing actually calls `get_api_Finnhub`; `main()` uses the working `get_quote_Finnhub` instead. So a genuinely broken function is invisible purely because it's never reached.

### Status

Identified during review. This is the same ghost as Day 10's "dead code after `return`" — now paired with a never-called duplicate. Deliberately **deferred**, not fixed, because I'm moving to MarketSync. Logged here so it's not silently forgotten.

### Lesson Learned

"It runs" hiding a bug, inverted: this time the code runs *because* the broken part is unreachable. Dead code doesn't announce itself — reachability is its own kind of test.

## Challenge 2 - The `if label == "Change %"` branch that does nothing *(understood, cleanup deferred)*

### Problem

In `difference_in_values` I special-cased `"Change %"`, believing that branch was where the `%` gets stripped to avoid a `ValueError` on subtraction.

### What I actually learned

The `%` is already stripped **upstream**: both values pass through `to_number()` (which does `.rstrip('%')` and `float(...)`) at the top of the loop, before the `if` is ever reached. By the time execution hits the branch, both values are already plain floats — and the two branches are byte-for-byte identical (`alpha_value - finnhub_value` in both). The guard instinct was right; it was just already handled one layer up. The branch is redundant and should be collapsed.

### Lesson Learned

Before adding a defence, check whether an earlier layer already handles it. Duplicated logic across two branches is a smell that the distinction isn't real.

## Challenge 3 - Alpha Vantage rate limit hit mid-testing *(this one was a win)*

### Problem

Testing stalled: Alpha Vantage started returning its rate-limit message instead of quotes.

### What happened

My body-check caught it and `sys.exit`'d cleanly with the provider's own explanation — which is exactly the "200-with-an-error-in-the-body" case I built the check for. The check working is the point; the cost is that with only ~25 requests/day on the free tier, I burned through the budget quickly and couldn't keep testing the Alpha Vantage path.

### Lesson Learned

The defensive check did its job — that's the success. But the real takeaway is bigger: a source with a 25/day free cap is a non-starter for anything that polls, which is a direct constraint on how MarketSync picks its data sources.

## Challenge 4 - Bad-symbol path untested *(open)*

### Problem

I tested with real US tickers. The nonsense-symbol path (e.g. `"ZZZZ"`) is unverified, and there's a likely `None`-handling gap: `difference_in_values` runs `.get()` on the quote **before** `print_comparison` applies its `or {}` defence, and Alpha Vantage runs first in `main()`.

### Status

Open. Same lesson as Day 10 — "test the input you didn't have in mind" — logged honestly rather than claimed as done.
